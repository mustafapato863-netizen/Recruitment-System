# RecruitFlow responsive audit

Measured from source on 2026-09-23. Phase 0 does not redesign these pages.

Runtime: not measured. This environment has no browser automation package installed, and Phase 0 must not add one. The 390 and 768 columns are intentionally empty of invented overflow results.

Severity is static only:

- P0: a min-width or fixed width of at least 220px, a raw table that is not inside an overflow container, or a kanban/calendar that is not in an overflow container.
- P1: a raw table already in a scroll container, a missing PageFrame, charts, side-by-side regions, filter bars outside DataToolbar, hard-coded max widths, or a page-owned stylesheet breakpoint.
- P2: no static overflow signal beyond the shared shell. PageEnhancementsV2.css is imported by many pages; its ad-hoc breakpoints are listed once below and are not repeated on every row.

Shared stylesheet `apps/web/src/pages/PageEnhancementsV2.css` (left unchanged in Phase 0) uses max-width 1199, 1023, 900, 760, 639, 520, and 420, plus min-width 640. Those values are not the canonical scale. Later page phases should remap only the rules for the page they are editing.

Page components scanned: 54 non-test modules in `apps/web/src/pages` (the brief estimated 55; that is the current file count). P0 9, P1 37, P2 8.

The canonical scale for later phases is Tailwind only: sm 640, md 768, lg 1024, xl 1280, 2xl 1536. The shell already switches the drawer and the sidebar at lg. Page CSS below was recorded and left unchanged.
