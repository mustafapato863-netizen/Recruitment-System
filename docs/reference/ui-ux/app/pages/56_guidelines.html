Guidelines

Follow the work as a pipeline: every stage has an owner, a permitted view, a decision, evidence, and a named handoff.

ROLE PLAYBOOK · STORY PIPELINE

From first request to trusted decision.

Use this page to guide a recruiter, an HR manager, and every approver through the same operating story. A stage is complete only when its evidence and next owner are clear.

The RecruitFlow operating pipelineRead left to right. The next owner receives a task only after the current stage is valid.
Story first
  1. 01
    RECRUITERRecruiter guide

    Sarah opens My Tasks and starts with the next candidate action, not a blank database.

    Can seeAssigned openings, candidate PII, consent, application stage, and feedback gaps.
    Can doCreate or edit a candidate, connect an application, move a stage, and schedule work.
    EvidenceReason for stage move + owner + next due task
    Hands offDecision-ready application to the Hiring Manager; scorecard task to the Interviewer.
  2. 02
    HIRING MANAGERManager guide

    Hassan turns the business need into a complete vacancy request with headcount, budget, and success criteria.

    Can seeOwned requests, role profile, department, branch, headcount, and approval status.
    Can doDraft, submit, comment, and respond to changes on requests he owns.
    EvidenceBusiness reason + budget context + requested headcount
    Hands offComplete request to the HR Manager for the first approval gate.
  3. 03
    HR MANAGERHR manager guide

    Ahmed sees the organization risk in one place and decides whether the request is safe to move forward.

    Can seeOrganization-level demand, salary bands, workflow evidence, owners, and audit context.
    Can doApprove, request changes, reject, manage HR data, and unblock the recruiting team.
    EvidenceApproval reason + policy check + next task created
    Hands offApproved opening to the Recruiter; controlled package to the Offer Approver.
  4. 04
    APPROVAL CYCLEApproval story

    The workflow never jumps from draft to final. Each approver receives only the decision assigned to that gate.

    1. 1
      HR reviewApprove vacancy or request changes.
    2. 2
      Offer reviewCheck compensation and salary band.
    3. 3
      Final gateConfirm documents, license, and readiness.
    EvidenceDecision, reason, actor, state transition, and timestamp
    Hands offOnly a valid approval creates the next owner task; a blocked gate stays visible.
  5. 05
    TRUST & AUDITClose the loop

    The final decision is useful only when another authorized person can understand how it was reached.

    Can seeAuthorized audit entries, decision evidence, task history, and current ownership.
    Can doReview history, resolve a blocked handoff, or request the missing evidence.
    EvidenceImmutable event + actor + object + result + timestamp
    Next storyJoining, reporting, or a controlled re-open with a new reason.

Recruiter checklistBefore sending work forward.
  1. ✓Candidate identity and consent are clear.
  2. ✓Application is linked to the correct opening.
  3. ✓Stage move includes a reason and next task.
  4. ✓Missing scorecard or document is visible.
HR Manager checklistBefore approving a gate.
  1. ✓Headcount and business need are supported.
  2. ✓Budget and salary policy are within band.
  3. ✓Approver ownership matches the role.
  4. ✓Decision reason will be auditable.
Approval cycle guardrailsNever bypass the next owner.
  1. ✓One gate has one accountable approver.
  2. ✓Pending evidence blocks the transition.
  3. ✓Reject and changes-requested states explain recovery.
  4. ✓Final approval is never implied by UI visibility.
